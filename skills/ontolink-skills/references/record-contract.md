# Task record contract

A task gets **one** `.ontolink/tasks/<id>.json` file and one RDF node with `taskRecord` and `taskRecordHash`. The JSON contains `formatVersion`, `id`, `uri`, `revision`, `updatedAt`, `properties` and `relationships`. Resource links such as `dependsOn`, `usesArtifact`, `derivedFrom` and `belongsTo` appear **only** in `relationships`, as deduplicated URI arrays. `phase` appears only in `properties`.

Use `record --json` to avoid creating an extra payload file. Minimum task fields: `id`, `type: "Task"`; initial tasks also need `phase`, `title`, `owner`, `status` and a `requiredKind` array. Existing fields are retained when omitted. Optional task-only sections include `files`, `proofs`, `artifacts`, `evidence`, `assessments`, `blockers`, `requirements`, `contracts`, `decisions`, `testResults`, `recommendations`, `risks`, `warnings`, `actors`, `communication` and `lastUpdate`. Empty sections are omitted. One record contains one task, not its entire history or copies of other tasks. Evidence and proof metadata are part of this task JSON, **not** a separate `.ontolink/evidence/` tree. Proof artifacts stay at their original paths.

`updatedAt` is generated by the mediator; `lastUpdate` is concise user-facing information about the latest work, not an accumulating events list. Revision is guarded by `--expected-revision`; SHA-256 is checked on read. Never edit generated task JSON directly without updating the canonical ontology.

Artifacts require `kind`, project-relative `path`, `contentHash` and `status`. Evidence requires `supports`, `outcome`, `proofPath`, `proofHash` and `targetHash`. DONE requires current PASS evidence. Legacy typed records remain supported, excluding new Event writes. The project adapter supports `record --save-record` to generate a minimal optional `.ontolink/records/revision-N.json` per accepted operation. It does not duplicate task details or add ontology Event nodes; without the flag no operation file is generated.
